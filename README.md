# Tabulation System

A modern, full-stack event tabulation system for pageants, competitions, and judged events.

## Stack (Updated July 2026)

| Layer | Package | Version |
|---|---|---|
| Framework | Nuxt | 4.5.x |
| Styling | Tailwind CSS (Vite plugin) | 4.x |
| ORM | Prisma ORM | 7.x (Rust-free) |
| Database | PostgreSQL | 16+ / 17 |
| Auth | nuxt-auth-utils | 0.5.x |
| Validation | Zod | 4.x |

## Architecture

```
Browser
  │
Nuxt 4 (Pages + Server API / Nitro)
  │
Prisma ORM 7 (via @prisma/adapter-pg)
  │
PostgreSQL
```

## Quick Start

### 1. Install dependencies

```bash
npm install
```

### 2. Configure environment

```bash
cp .env.example .env
```

Edit `.env`:
```env
DATABASE_URL="postgresql://postgres:password@localhost:5432/tabulation_db?schema=public"
NUXT_SESSION_PASSWORD="generate-a-random-string-of-at-least-32-chars"
```

Generate a session password:
```bash
openssl rand -base64 32
```

### 3. Set up the database

```bash
# Run migrations (creates all tables)
npm run db:migrate

# Generate the Prisma client
npm run db:generate

# Seed the default admin account
npm run db:seed
```

Default admin credentials (change immediately!):
- **Email:** `admin@tabulation.local`
- **Password:** `Admin1234!`

### 4. Start the dev server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

| Role | Can do |
|---|---|
| **ADMIN** | Manage events, criteria, contestants, assign judges, view all results |
| **JUDGE** | View assigned events, submit & edit scores |

## Scoring Logic

Scores are submitted per contestant per criteria per judge. The results endpoint:

1. Groups scores by `(contestantId, criteriaId)` and averages across judges
2. Multiplies each average by that criteria's `weight / 100`
3. Sums the weighted averages into a final score out of the total weight
4. Ranks contestants by weighted total, descending

The `@@unique` constraint on `Score` prevents a judge from submitting duplicate scores for the same `(event, judge, contestant, criteria)` tuple. Resubmitting uses `upsert`.

## Prisma 7 Config Split (Important)

Prisma 7 removed `url` from `schema.prisma`. Connection config is now split:

| Where | Purpose |
|---|---|
| `prisma.config.ts` → `datasource.url` | Used by CLI: `migrate`, `studio` |
| `server/utils/prisma.ts` → `@prisma/adapter-pg` | Used at runtime by the app |

Both read from the same `DATABASE_URL` env var. You do **not** need to change anything — just make sure `.env` has a valid `DATABASE_URL`.

## Database Scripts

```bash
npm run db:migrate      # Run pending migrations
npm run db:generate     # Regenerate Prisma client after schema changes
npm run db:studio       # Open Prisma Studio (visual DB browser)
npm run db:seed         # Create default admin account
npm run db:reset        # Reset DB + re-run all migrations (dev only!)
```

## Deployment

**App:** Deploy to [Vercel](https://vercel.com) (supports Nuxt/Nitro natively)

**Database:** [Neon](https://neon.tech), [Supabase](https://supabase.com), [Railway](https://railway.app), or self-hosted PostgreSQL

Set `DATABASE_URL` and `NUXT_SESSION_PASSWORD` as environment variables in your deployment platform.
